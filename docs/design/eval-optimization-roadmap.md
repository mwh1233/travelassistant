## 0. 先回答：链路设计完了吗

**分三层看，答案不同。**

| 层 | 问题 | 状态 |
|---|---|---|
| **目标架构** | 知道要建成什么样的评测体系吗 | ✅ 已完成 —— `evaluation-system-design.md` 已给出 D09 九宫格的本地映射与 Phase A–D |
| **执行链路** | 能跑起来吗 | ✅ 已跑通 —— 离线确定性回归链路可执行、可出报告、可作退出码门禁 |
| **覆盖完整度** | 覆盖了 D09 的多少 | 🔴 只覆盖 **3½ / 9 格**，且**整行轮次层为空** |

所以准确的说法是：**"离线回归链路"设计并跑通了；"评测体系"（D09 的粒度 × 目的）远没完。**

现状数字：

```
L0  12/12 通过
L2  pass@1 9/10（1 项 known_gap：高风险审批仅 prompt 软约束）
```

**一句话诊断**：现在织出的是**一条线**（离线 → 断言 → 报告 → 退出码），D09 要的是**一张网**（结果/轨迹/轮次 × 门禁/刻画/对标，外加离线在线两条腿）。这条线只占了那张网的一列。

## 1. 优化思路：四条主线 + 三条红线

### 四条主线（做加法时按这个想）

1. **以 D09 九宫格当覆盖刻度，不追总分。** 每加一个东西，先问它点亮哪一格。`pass@1 = 0.9` 不是可验收的表述；"结果层 × 回归门禁 已点亮"才是。
2. **以 D09 六环节当施工顺序。** ②数据 → ③环境 → ④轨迹 → ⑤打分 → ⑥门禁 → 闭环。**不跳步**：没有可复现环境（③）就先上 Judge（⑤），产出的分数不可复现，等于白做。
3. **以 D09 §8 MVP 七项当里程碑。** 七项就是七个可勾选的关卡；每勾掉一项，九宫格里应当有格子变绿。若某项做完没有任何格子变色，说明做错了地方。
4. **阈值本地标定。** D09 §8 的参考阈值（成功率 ≥ 90%、`pass^k` 与 `pass@1` 差距 ≤ 5pt、安全项 0 容忍）只作起点，必须在本项目基线上重新标定，并把阈值当配置**版本化**。

### 三条红线（做减法时的理由）

1. **硬门禁不参与平均。** 安全违规、越权、schema 失败、审批缺失一律独立为硬失败，不得被质量分稀释（D09 §7.4）。
2. **没有 rubric 的 Judge 不许进自动门禁**，且必须先过人工校准 —— **Cohen's kappa ≥ 0.6**（D09 §5.2）。不达标的 Judge 只能做粗筛，最终判定回流人工。
3. **未经人工复核的线上分歧不得入库。** 否则会把错误行为固化成标准答案（D09 §7.7 与 §3 闭环）。

## 3. 按六环节的差距与补齐动作

### ① 定义成功标准

| 项 | 内容 |
|---|---|
| D09 要求 | 把"什么叫做完了"写成**机器可判定**；口径以**系统端状态**为主，不只最终文本 |
| 当前 | 轨迹场景有结构化终态断言；240 条内容用例**没有**"期望终态"定义 |
| 差距 | 内容用例只能做 schema 校验，无法判定"做完没" |
| 补齐动作 | 为每类数据集定义 `expect`（必需字段 / 允许的替代路径 / 禁止行为 / 判定所需证据） |
| 验收判据 | 每条用例都能回答"什么算做完"，且由代码而非人眼判定 |

### ② 数据集

| 项 | 内容 |
|---|---|
| D09 要求 | 版本化、分层、抗污染、有刷新协议 |
| 当前 | v0.2.0 schema + split / version / initial_state / metadata 已统一 |
| 差距 | 无 holdout 隔离执行；无退役 / 刷新协议；无抗污染检查（答案是否泄漏进 prompt / 检索库） |
| 补齐动作 | 建 holdout 池并**禁止其参与任何调优**；写数据集刷新协议（期限、退役规则、复核要求） |
| 验收判据 | 能证明 holdout 未被任何 prompt / 检索调优引用 |

### ③ 环境与沙箱

| 项 | 内容 |
|---|---|
| D09 要求 | 可重置、隔离、并行限流、幂等重入、外部依赖固定或录制 |
| 当前 | deterministic 每场景新建 `MemorySaver`（**隔离 ✅**）；只换模型 / checkpointer / 记忆 / 非确定性工具，图拓扑与状态机是真代码 |
| 差距 | 无 `(case_id, run_id)` 结果存储与幂等重跑；无外部依赖录制；非法起始态矩阵未覆盖 |
| 补齐动作 | 结果按 `(case_id, run_id)` 落库、重跑**覆盖而非追加**；补"某步非法起始态"断言矩阵（如 `transport_planning` 但缺 `selected_destination`） |
| 验收判据 | 一条用例失败后，能在本地复现出同样失败 |

### ④ 采集轨迹

| 项 | 内容 |
|---|---|
| D09 要求 | 完整序列（模型 / 工具名参 / 状态转移 / 中间产物 / 重试 / 记忆读写 / 子 Agent 交接 / 每步 token 费用耗时），建议对齐 OTel span 语义 |
| 当前 | `trace.py` 已记节点、工具名与参数、结果摘要、状态写入、终态快照、总 token / 调用 / 总耗时；带 `case_id` / `run_id` / `dataset_version` / `prompt_version` / `schema_version` |
| 差距 | 逐步成本（非总量）、延迟分位数、父子 span 归因、**工具完整返回值**（Replay 的前提）、代码 SHA 未进 trace |
| 补齐动作 | 补父子 span 与逐节点计量；把工具返回值单列录制；trace 头加代码 SHA |
| 验收判据 | 任一失败能定位到"哪个节点 → 哪个工具 → 哪一轮"三级 |

### ⑤ 三层打分

| 项 | 内容 |
|---|---|
| D09 要求 | 确定性断言 → LLM-as-Judge → 人工，成本递增漏斗；Judge 必须 rubric 化 + 版本化 + kappa ≥ 0.6 校准 |
| 当前 | 只有第一层（确定性断言，L0 + L2），实现充分 |
| 差距 | 无 Judge rubric / 版本控制 / 校准；无人工抽检队列 |
| 补齐动作 | 见 Wave 4；先解决"给什么打分"（见 §7 不做清单第 1 条） |
| 验收判据 | Judge 与人工盲评的 Cohen's kappa ≥ 0.6 才允许进自动门禁 |

### ⑥ 聚合、切片与门禁

| 项 | 内容 |
|---|---|
| D09 要求 | 不报单一总分；按任务类型 / 难度 / 模型版本 / 工具条件切片；四项发布门禁；一次只改一个变量 |
| 当前 | 有 case 级、split 级、`pass@1` / `pass^k`、非零退出码 |
| 差距 | 无阈值体系、无按任务类型 / 难度 / 风险的切片、无相对 baseline 的下降阈值比较 |
| 补齐动作 | 阈值配置化并从基线标定；加 baseline diff（"相对上次下降 X"才是有用信号） |
| 验收判据 | 回归报告能报出"某切片相对 baseline 下降 N pt"，而不是只有一个总分 |

### 闭环

| 项 | 内容 |
|---|---|
| D09 要求 | 线上标注 → **人工复核** → 刷新数据集 → 更新门禁 → 再发版 |
| 当前 | 有可选的线上 trace 旁路采集（`EVAL_TRACE_ENABLED`），**但开关 ≠ 闭环** |
| 差距 | 逐轮分类、标注队列、复核流程、回流机制全缺 |
| 补齐动作 | 见 Wave 5 |
| 验收判据 | 线上样本经人工确认后才可能成为用例，且能追溯到确认人 |

## 5. 执行排期（Wave，逐波可独立验收）

依赖关系：**W1 必须先做**（否则后面全建在流沙上）；W2 与 W4 可并行；W3 依赖 W2（需要多轮轨迹）与 W4（需要判定器）；W5 依赖 W3。

### Wave 1 · 闭合离线结果链路 → 点亮「结果层 × 回归门禁」

- 把 `grade_travel_state` 及硬门禁接入 `runner`，纳入每个适用 case 的最终 verdict。
- 让 240 条内容用例**真的被执行**（或为每类定义显式执行器与判分器），并在报告里区分「结构校验样本数」与「行为执行样本数」。
- `smoke` / `regression` / `safety` 支持按 split 独立执行与报告。
- 关键 safety 场景升为硬门禁；`known_gap` 只是迁移期清单，**不得当作已满足安全要求**。

**验收**：回归报告里"执行量"与"校验量"分开列；安全硬门禁失败必然让 suite 失败；任一 case 的通过可由代码判定且能定位到断言的哪一轴。

### Wave 2 · Replay + 轨迹深挖 → 点亮「轨迹层 × 选型对标」

- 录制 `on_tool_end` 的工具入参 / 返回值，新增 `--mode replay`；书写录制版本失效策略。
- trace 补父子 span 归因、逐节点成本与延迟、重试信息。
- 报告补 P50 / P95 / P99 与单任务成本。

**验收**：同一份录制下，切模型 / prompt / 图版本时指标变化能**唯一**归因到被改的那一个变量；一次 `--diff` 能报出两个版本在哪一格上差了。

### Wave 3 · 轮次层 → 点亮「轮次层 × 回归门禁」与「轮次层 × 能力刻画」

- 建多轮场景：固定剧本（可复现）+ 受控 user simulator（persona + 隐藏目标 + 干扰行为：中途改口、撤回、打断）。
- 测意图保持率、约束保持率、澄清时机、多轮改需求后的状态一致性。
- 模拟器**必须版本化**，并定期人工抽检其行为是否合理。

**验收**：能报出"改预算后行程是否同步""改目的地后旧数据是否清理"这类多轮断言，且不依赖线上流量。

### Wave 4 · Judge 与校准 → 点亮「结果层 × 能力刻画」的质量维度

- 结构化 rubric（3–5 维、每维 0–1 并附理由），Judge prompt 版本控制 + 回归测试。
- 防冗长 / 位置 / 自我增强三类偏见；要求先给证据再打分。
- 与人工盲评算 Cohen's kappa，**≥ 0.6 才允许自动打分**。

**验收**：Judge 有版本号、有校准报告（kappa 值）、有不达标时的降级路径。

### Wave 5 · 在线反馈闭环 → 点亮「轮次层 × 门禁」的在线侧

- 线上 trace 脱敏 → 抽样 → 逐轮轻量分类 → 低置信 / 高风险进人工复核队列。
- 人工确认"正确行为应该是什么"后，才允许更新版本化数据集并跑回归。
- 分类器独立校准、版本控制、漂移检查。

**验收**：能演示一条线上失败 → 人工复核 → 变成永久用例 → CI 抓住的完整路径。

### Wave 6 · 能力刻画与选型对标 → 补齐「能力刻画」列与「选型对标」列

- 建 holdout 与 challenge 维护规则，按任务长度、前置依赖、故障注入扩展能力边界。
- 用 Replay 冻结工具层，一次只变一个变量；必要时做受控因子实验。
- 对标表 = 稳定性 + 结果质量 + 安全 + 成本 + 尾延迟；外部基准只作补充。

**验收**：有一张按版本切片的对标表，且每行都注明执行模式与模型 / 提示版本。

## 6. 报告必须写明的元信息

每份评测报告需注明，否则结论不可追溯（D09 §6「所有数字必须可追溯」）：

代码 SHA · 数据集版本 · schema 版本 · 执行模式 · 模型及参数 · 提示版本 · 重复次数 · 有效样本数 · 排除的 known gap · Judge / 分类器版本 · kappa 校准值

---

## 7. 不做清单（显式划界）

1. **不对行程 / 预算的"内容质量"做 LLM Judge。** 它们由 `build_itinerary_plan()` / `estimate_budget()` 纯代码生成，Judge 打的是**代码的分不是模型的分**。这两步要测的是"LLM 有没有在正确时机调工具、参数对不对、调用前有没有完成用户确认"。
2. **不要求工具调用唯一顺序。** 用子集 / 包含模式比对，只约束工具集合、参数与最终状态。
3. **不把公开基准当验收标准。** 只作选型入场筛选；所有固定基准都会饱和（D09 §6）。
4. **不把"数据集结构校验通过"说成"Agent 跑过"。** 两者在两个不同分母上。
5. **不在 PR 门禁里跑 Live。** 外部 API 非确定，PR 只用 deterministic（Replay 到位后可用 Replay）。
6. **不把 `known_gap` 计入通过。** 它是待修清单，不是豁免。

## 8. 风险与回退

| 风险 | 影响 | 应对 |
|---|---|---|
| `live` 依赖外部 API（dashscope / amap）超时或限流 | 评测跑挂、结果不可复现 | PR 只用 deterministic；live 只在 nightly / 发版前跑 |
| `food.search` 已在词表但**无 MCP server 实现** | `mcp_food_halal_049` / `mcp_food_low_spice_050` 无真实行为可测 | 接上真实 server 前不作为回归目标 |
| P0-5 审批软约束未修 | 安全断言长期红 | 保持 `known_gap` 并在 W1 的 safety suite 里作为**已知未达标项**显式列出，不混入普通失败统计 |
| 线上 trace 含用户数据 / 凭证 | 送去做 Judge 或观测前泄漏 | 先脱敏再出网；设保留期限（D09 §7.6） |
| `fastmcp` 未安装 | 自建 MCP server 加载失败 | `_load_tools_best_effort` 已兜住，不影响离线评测；接 MCP 专项前需补装 |
